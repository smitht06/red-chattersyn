# M4 — Chatterino parity (design)

Design companion to the approved plan. Where reality (verified against the codebase and the
platform APIs) differs from the plan, this document supersedes it.

## Milestone decisions (user-confirmed 2026-10-16)

- **YouTube moderation** = server ban (`liveChatBans.insert`/`delete`, ~50 quota units each,
  existing `force-ssl` OAuth scope) + **local hide** for "delete". The Data API has **no**
  `liveChatMessages.delete` (verified) and tombstones carry no deleted-message id, so a local
  hide can never correlate to a server event — hide is self-only.
- **Twitch moderation** = IRC chat commands via PRIVMSG (what Chatterino itself sends), current
  `chat:read chat:edit` scopes, no forced re-auth. Failure feedback mapped from NOTICE msg-ids
  (`msg_rejected`, `no_permission`, `msg_cmd_rejected`). `/delete` (Helix Delete Chat Messages,
  needs `channel:moderate`) deferred.
- **User commands** live in `commands.json` under `config_dir()` (Chatterino parity). The
  settings `commands: []` key stays unused.
- **Emote picker**: `tag:` filters dropped (7TV/BTTV/FFZ expose no tags without per-emote API
  calls); free-text search ships. Emojis tab = bundled emoji shortcode dataset. Favourites =
  persisted settings key.
- **"Connect Twitch" menu item lands in M4** — auth-gated features (commands, moderation) need a
  recovery path, and `TwitchAuth.begin_flow`/`wait_for_code` exist with no UI caller today.

## Feature readiness (from the codebase map)

READY — plumbing exists, only feature code is missing:

- **Reply**: send-side reply-parent tags are threaded end-to-end (`SendCoordinator.send` →
  `TwitchIrc.send` reply-parent-msg-id/login), inbound `REPLY` flag + `reply_parent(_name)`
  rendering exists in the delegate. Missing: reply banner UI, `/reply`, context-menu Reply
  action, `_make_optimistic` reply fields, YouTube `@name` degradation.
- **Usercard**: click chain fully wired (`delegate.hit_test` → `ChatView.usercard_requested` →
  `Tab` → `MainWindow._show_usercard_hint` stub). Missing: popup widget, Helix field expansion,
  recent-messages scan, conditional moderation-actions section.
- **Highlights/mentions**: `HIGHLIGHTED` flag + delegate tint render today; nothing ever sets
  the flag. Missing: matcher, sound, `/mentions` store.
- **Search**: greenfield; every predicate input exists (`plain`, `Author.badges`, `Platform`,
  `extra`).
- **Logging**: greenfield, zero dependencies.

BLOCKED — unblocks in build order:

- **Autocomplete**: needs the command registry (step 3), the popup pattern (step 5), and a
  per-tab chatter index (`@` has no data source today: Names/353 is emitted and dropped).
- **Commands**: parser + registry + commands.json loader. Interception MUST run before
  `SendCoordinator._validate` — unhandled slash commands currently leak as literal chat text to
  BOTH platforms (only `/me` is intercepted).
- **Emote picker**: registry refactor (scope retention, BTTV channel/global distinction
  destroyed at fetch, global Twitch set never fetched), emoji dataset, favourites,
  insert-at-cursor.
- **Moderation mode**: last — IRC mod-command sender, USERSTATE parsing (self mod status is not
  parsed anywhere today), NOTICE msg-id feedback mapping, `YouTubeApi` ban methods + QUOTA
  entries, local-hide delete.

## Build order

1. **Settings foundations** — add keys (`highlight_color`, `favourites`, `logging.*`,
   autocomplete prefs) + a save discipline. `Settings.set` does not auto-save today; only
   theme/zoom call `save()` — every M4 feature mutating settings would otherwise lose state on
   quit.
2. **Per-channel text logging** — ingress subscriber on `bridge.message`; establishes the
   pattern highlights/mentions/chatter-index reuse; backing store for search and
   usercard-recent beyond the 1000-row scrollback.
3. **Command core without mod built-ins** — parser + registry + commands.json loader;
   `/reply /clear /clearmessages` + the full built-in table (mod commands stubbed until step 9);
   command-result system rows; interception at `_queue_send`.
4. **Reply** — banner (copy the `Tab._offer_banner` pattern), context-menu Reply action, pass
   reply args in `_queue_send`, fix `_make_optimistic`, YouTube `@name` degradation,
   lowercase-login resolution via `message_by_id`, banner-vs-offer slot precedence.
5. **Popup infra + Ctrl+F search** — first frameless popup widget (shared later by
   usercard/autocomplete/picker); predicate engine (`from:`/`badge:`/`in:`/`is:`/`has:link`/
   `regex:` + `!` negation); RoomState retention per channel; in-memory scan first.
6. **Highlights/mentions + sound** — matcher at ingress, sets `HIGHLIGHTED`, `QSoundEffect`
   (QtMultimedia is bundled in the PySide6 wheel — no new dependency; needs an asset file),
   `/mentions` view.
7. **Usercard popup** — Helix field expansion + Author-based fallback for anonymous rows +
   recent-messages scan + conditional moderation section.
8. **Autocomplete, then emote picker** — completer needs steps 3+5 plus the chatter index;
   picker needs the registry refactor, emoji dataset, favourites, insert-at-cursor.
9. **Moderation mode** — IRC mod-command sender, USERSTATE + GLOBALUSERSTATE badge capture,
   NOTICE msg-id feedback, YouTubeApi ban methods + QUOTA entries, local-hide delete,
   moderation rows.

## Cross-cutting risks (from the adversarial critique)

- **MainWindow is a 512-line god object** and 7/9 features touch it — extract per-feature
  controllers (CommandController, ChatIndex, ModerationState, LogSink) as features land.
- **Delegate layout cache** keys on `(msg.id, width, dpr)` — flags excluded, so strikethrough/
  reply-prefix changes on visible rows won't repaint via `dataChanged`. Fix the cache key or
  invalidation early (steps 1–4).
- **Scrollback (1000 rows)** silently bounds search, /mentions, usercard-recent, and
  reply-parent resolution — ingress recording (step 2) is the mitigation.
- **Registry lifecycle** is hostile to M4 UI: single instance on `TwitchService`, non-Twitch
  maps cleared mid-refetch on channel switch, BTTV channel/global distinction destroyed at
  fetch, FFZ keyed by channel name (rename-sensitive).
- **Counter/validation drift**: input counters count raw text while `prepare_twitch_send` and
  truncation apply later — reply prefixes and command expansion must sync the counters.
- **UI test harness exists** (pytest-qt + session `qapp` fixture + `test_delegate.py`
  precedent; `fakeirc.py` reusable). The real gap is MainWindow/Tab/InputWidget wiring tests,
  and the fixture corpus lacks USERSTATE lines (add for mod-status tests).
- **Shutdown drain**: app.py's `_main` blanket-cancels tasks after `window.shutdown()` — the
  log writer must flush during shutdown or lose tail lines.

## Chatterino parity notes (verified against chatterino2 master, 2026-10-16)

Synthesized from a source-level parity research pass (twitch APIs, search predicate engine,
CommandController, UserInfoPopup, completion sources, EmotePopup, reply/thread handling,
moderation surfaces). Where a Chatterino behavior conflicts with a milestone decision above,
the milestone decision wins and the divergence is recorded here.

### Commands

- **Dispatch order** (mirror exactly): emoji shortcode replacement → split on spaces → if the
  first word matches a USER command, substitute its func and re-run the whole pipeline (custom
  commands can emit builtins) → match builtins by first word → match multi-word user triggers
  (up to a max-spaces setting) → return text unchanged. **User triggers shadow builtins.**
- **Typed triggers match only at message start.** The wiki's "match at the end" setting is stale
  — does not exist in master. Input live-previews substitution via dry-run as you type.
- **commands.json**: `{"commands": [{"name", "func", "showInMsgContextMenu"}]}` (all three
  required), lives in the settings/config dir. Placeholder grammar:
  `(^|[^{])({{)*{(\d+\+?|([a-zA-Z.-]+)(?:;(.+?))?})}` — `{N}` word N after trigger, `{N+}`
  words N..end, `{var;fallback}` fallback when empty, `{{1}` escapes to literal `{1}`, unknown
  names stay literal, out-of-range `{N}` → empty string.
- **Named vars**: `{channel.name}`, `{channel.id}`, `{stream.game}`, `{stream.title}`,
  `{my.id}`, `{my.name}`, `{user.name}`, `{msg.id}`, `{msg.text}`, `{input.text}`,
  `{element.copytext}` (context-menu/hotkey runs only) + deprecated aliases `{channel}`,
  `{user}`, `{msg-id}`, `{message}` — keep the aliases so imported Chatterino commands.json
  files work.
- **`/me` is NOT a client command** — it is a pass-through whitelist entry: the unknown-command
  send guard explicitly lets `/me …`/`.me …` reach Twitch (server renders ACTION) while
  blocking unknown `/…` sends. Same pass-through covers `/help /disconnect /host /unhost`.
  Commands have NO static usage field — usage is runtime system rows + the wiki; author ours
  per platform.
- **Builtin tables** (arg syntax + misuse system rows): moderator/broadcaster — `/ban
  [options] <username> [reason]`, `/banid`, `/timeout [options] <username> [dur][unit]
  [reason]` (default 10 min, units s/m/h/d/w, max 2w, combos like `1d2h`, repeatable
  `--channel`), `/untimeout`, `/unban`, `/warn <username> <reason>`, `/delete <msg-id>`
  (UUID-validated), `/clear`, `/mod /unmod /vip /unvip`, `/announce[blue|green|orange|purple]`,
  `/raid /unraid`, `/shoutout`, `/commercial <30|60|90|120|150|180>`, `/shield /shieldoff`,
  `/monitor /restrict /unmonitor /unrestrict`, `/mods`, `/vips`, `/marker [desc]` (140-char
  crop), `/clip`, `/settitle`, `/setgame`, `/color`; chat modes — `/slow [sec] /slowoff`,
  `/followers [dur] /followersoff`, `/emoteonly[off]`, `/subscribers[off]`,
  `/uniquechat = /r9kbeta (+off)`; engagement — `/poll --title --duration --choice x2-5
  [--points]`, `/prediction --title --choice x2-10 --duration` (+ cancel/lock/complete),
  `/pin --duration | --id (+ /unpin)`; user-level — `/reply <username> <message>` (NOT a
  message id), `/w`/`.w` whisper, `/r` input rewrite (not a registered command), `/block
  /unblock`, `/user`, `/usercard <login|id:>`, `/requests`, `/lowtrust`, `/popout`, `/popup`,
  `/streamlink`, `/uptime`, `/openurl`, `/copy <text>`, `/raw`, `/clearmessages` (local visual
  clear — distinct from `/clear`), deprecated forwarders `/ignore /unignore /follow /unfollow`.
- **Dual-platform**: per-platform command tables; every Twitch mod/broadcaster/chat-mode
  command yields a graceful "not available on YouTube" system row instead of the Twitch-guard
  text. `{channel.id}` on YouTube = channel id, `{stream.game}/{stream.title}` render
  fallback. YouTube-applicable set: `/openurl /copy /clearmessages` + local views.

### Search popup (Ctrl+F / Ctrl+Shift+F)

- Ctrl+F = focused split only; Ctrl+Shift+F = every split of every page of the MAIN window
  (not other windows). Top-level popup (~400x600), never a new split/tab. Input pre-filled
  with the source view's text selection, first search runs on show; every keystroke re-runs
  the search but the **snapshot is built ONCE** — messages arriving after open are excluded.
  Results capped at the scrollback limit (default 1000); result rows are do-not-log.
- **Tokenizer**: `(negation[!-])?(name\w+):(value "..."|[^\s]+) | [^\s]+?(?=$|\s)`. Typed
  predicates: `from:` (display OR login, ci), `in:` (channel name, ci), `badge:` (ci keys,
  short forms mod→moderator sub→subscriber prime→premium), `subtier:` (first char of
  `subscriber/<value>` when len>3, else '1'; case-SENSITIVE contains), `regex:` (ci, unanchored
  match against plain text ONLY, invalid → matches nothing), `has:link` (TLD/IPv4 word parse,
  not regex), `is:` (any-of: deleted|disabled, sub|subscription, timeout|ban, highlighted,
  system, first-msg, cheer-msg, redemption, reply, restricted, monitored, shared, watch-streak,
  announcement; unknown names match nothing — negated unknown matches EVERYTHING). Unknown
  `name:value` → literal substring of the whole token. Quoted values strip quotes.
- **Negation**: `!`/`-` immediately before a predicate NAME negates that predicate; a bare
  `!word` (no colon) is NOT negated. Predicates AND; comma values inside a predicate OR.
  Bare words match case-insensitively over a searchText = username variants + content.
- **Navigation**: right-click "Go to message" scrolls the source view (delegates cross-window
  for aggregator channels); no next/prev, no result-count label. Escape closes; Ctrl+F
  refocuses input+selectAll; PgUp/PgDn scroll.
- **Divergences**: add a match timeout to `regex:` (Chatterino has none — pathological
  patterns freeze the UI thread); `badge:` checks the merged Twitch+YouTube badge list; `in:`
  namespaces per platform (`twitch:x` vs `youtube:x`) to avoid merged-feed collisions; YouTube
  `is:` mappings = membership/sponsor, super chat/sticker, system, highlighted. Add a
  YouTube-compatible `has:link` TLD list (root-zone, minor mismatches accepted).

### Usercard

- Opens on username click, positioned at the cursor, auto-close-on-focus-loss setting + pin.
  Resolves login or `id:`-prefixed id. Rows: avatar (100x100, left-click opens channel page,
  right-click menu copy/open), display name + "Copy localized name" when display≠login,
  `ID: <id>`, `Created: YYYY-MM-DD` (+ duration tooltip), `Followers: %1`, followage
  (broadcaster-or-mod gated), subage (Twitch-only, third-party IVR API), pronouns
  (third-party, setting-gated), live indicator, local notes. **NO badge display in the
  usercard — parity says don't render badges.**
- **Moderation is buttons, not a menu**: Unban + timeout duration strip (default
  {1s,30s,1m,5m,30m,1h,1d,1w}) + Ban, visible only with mod rights and target≠self; they
  execute the command text (`/ban <user>` etc.). Block checkbox warns first; "Ignore
  highlights" toggles a local highlight-suppression entry.
- Recent-messages section: filter the channel's local scrollback for the user's messages
  (login match, sub-message prefix match, timeoutUser match; whispers excluded), live-appended,
  "No recent messages" empty state.
- **Dual-platform**: followers→subscribers (hide without a Data API key); Created = channel
  publishedAt on YouTube (label the row per platform); followage/subage/pronouns rows
  Twitch-only; mod/unmod/vip buttons hidden on YouTube; timeout strip becomes a fixed
  300s timeout + ban/unban per the milestone decision; YouTube recent-messages scans only
  client-fetched messages (no scrollback API); avatar opens `youtube.com/@<handle>`;
  popout-usercard button Twitch-only.

### Autocomplete (popup + Tab are TWO mechanisms)

- **Popup** (frameless, DontFocus, above the input): `:` → emotes (thumbnail + name +
  provider label), `@` → users (plain names, chatters snapshot + broadcaster). Never serves
  `/`-commands. Enter/Tab accept, Up/Down wrap, Escape closes. Hard cap 200 results; selection
  resets on every keystroke. Emote matching: case-insensitive contains, exact match hoisted to
  index 0, `~` prefix = zero-width only. User matching: prefix-only.
- **Tab cycling** (InlineCompletion QCompleter): word ≥2 chars; `@`→users, `:`→emotes, first
  word `/`/`.`→commands, first word otherwise→emote+user+command unified, mid-message→
  emote+user only. Command matching prefix-only ci after stripping the prefix; emote matching
  start-of-word by default (`prefixOnlyEmoteCompletion`=true); emojis complete only as
  `:shortcode:`. Accept inserts `name` / `@name` with a trailing space, comma-append only for
  first word and only when `mentionUsersWithComma`=true. Reply prefix (`@Name` + space, set
  while replying) is ignored for first-word detection.
- **Dual-platform**: Chatterino gates both systems on Twitch channels — we lift the gate:
  `@` completes from the YouTube chatters snapshot; `:` degrades to emoji-only on
  YouTube-only splits; per-platform default command lists.

### Emote picker

- Persisted-bounds popup (default 300x500), emote button next to the input or Ctrl+E. Five
  tabs in order **Favourite, Subs, Channel, Global, Emojis**; default selected = **Subs**.
  Subs = Twitch sets ("&lt;channel&gt; (Follower)" + access sets, current channel first); Channel =
  channel BTTV/FFZ/7TV; Global = global BTTV/FFZ/7TV; Emojis = categories with headers
  (Component category moved last).
- Search box hides the tab bar while non-empty; `tag:X` tokens + one free word (substring
  matching on name/baseName; tags substring-matched). Clicking inserts (emote name / emoji
  `:shortcode:`). Favourites: Ctrl+click toggles, Ctrl+Shift+click toggles+inserts, right-click
  checkable action; persisted as two names-only lists; unresolved favourites render as plain
  names under a notice. Keyboard: Esc, Ctrl+1..9 tabs, Ctrl+Tab, PgUp/PgDn, Ctrl+F search.
- **Divergences** (milestone decisions): `tag:` filters dropped (providers expose no tags
  without per-emote API calls); Emojis tab = bundled emoji dataset; default tab Emojis for
  YouTube-only splits; the emote button stays visible on YouTube splits.

### Replies / threads

- Reply banner prepends `@&lt;displayName&gt;` + space into the input (with careful
  partial-mention handling), shows a parent preview + cancel X; switching targets replaces the
  prefix; clearing the input clears reply state. Send strips the prefix, then runs commands,
  then sends with reply-parent-msg-id (+login).
- Inline reply header: "Replying to" + `@&lt;parent&gt;` in the parent's username color + the
  parent's full text on ONE line in the parent's color; fallback to reply-parent-display-name
  / -msg-body IRC tags when the parent is not in local history.
- `/reply` takes a **username**, not an id — searches the snapshot backwards for that user's
  most recent message.
- **Dual-platform**: YouTube has NO reply protocol (no reply-parent tags, no
  replyParentMessageID) — reply UI is Twitch-only; on YouTube the context-menu action inserts
  a plain `@Name` mention (with trailing space). Do NOT synthesize an inline reply header for
  YouTube.
- Thread popup (`Reply Thread - @<root> in #<channel>`, replies chain to root) is
  nice-to-have, not core M4.

### Moderation mode

- Per-split shield toggle in the header; ON = one button per configured moderation action
  rendered on every regular message (except the broadcaster's own and mods'), plus collapsed
  messages expand. Actions are a GLOBAL list of command templates (default EMPTY) with
  `{user.name}/{msg.id}/{msg.text}/{channel.name}` placeholders; clicking runs the template
  through the command engine then sends the result.
- Message context menu: "Moderate" submenu = Delete message + Pin (no timeout/ban entries —
  those live on the usercard buttons). Deleted/timed-out messages stay visible, grayed
  ("disabled" overlay); CLEARCHAT without user → "Chat has been cleared by a moderator." +
  disable all; with user → "&lt;user&gt; has been timed out for &lt;dur&gt;." / "permanently banned.".
  Timeout/ban system rows stack "(N times)" within a 5s/20-message window (default: stop
  stacking when the user posts again). Mod-action rows have visibility settings (shown by
  default).
- hasModRights = own PRIVMSG/USERSTATE badges (moderator/lead_moderator/mod=1) or
  broadcaster by name. Chatterino's mod commands are Helix-backed; **ours are IRC PRIVMSG +
  NOTICE msg-id feedback per the milestone decision** (`/delete` deferred).
- **Dual-platform** (milestone decisions): YouTube mod status has no in-feed signal — derive
  from channel ownership (mine=true) or hide the shield; YouTube actions = server ban
  (`liveChatBans.insert/delete`) + local hide for delete + fixed 300s timeout; YouTube has no
  AutoMod hold/allow/deny (Studio-only) — Twitch-only; chat-mode menu is ROOMSTATE-driven,
  YouTube exposes slow mode only.
